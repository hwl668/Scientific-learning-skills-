# 设计理念

## 为什么做这个项目

现有的 AI 辅助学习存在几个通病：

1. **百科式回答**：问一个概念，AI 返回维基百科式的长篇定义和历史背景，但学习者真正需要的是理解这个概念的"入口"。
2. **没有诊断**：AI 假设学习者需要从头学起，但实际上大多数时候学习者只是某一步卡住了。重新讲一遍整个概念是浪费时间。
3. **只会正面讲**：AI 只讲"是什么"和"怎样是对的"，但不讲"常见错误是什么"和"为什么有人会这样错"。后者往往比前者更有教学价值。
4. **给答案不给方法**：解题时直接给完整解答，没有思路推演和方法总结。

这个项目试图用结构化的 Skills 来解决这些问题。

## 核心设计原则

### 1. 诊断先于讲解

在任何解释之前，必须先判断学习者当前处于什么阶段、卡在哪里。不同的卡点需要完全不同的修复策略。

### 2. 直觉先于定义

人对事物的理解从直觉开始，然后才是形式化。零基础学习时，先给直觉（"这个东西在解决什么问题"），再给定义。

### 3. 最小可运行

每个 Skill 都应该提供"最小例题"——一个最简单、数字最干净、能跑通的例子。复杂例子里学习者会迷失在细节中。

### 4. 理解通过迁移验证

学习者的"我懂了"可能是假的。只有能解决变式题（改了条件或场景的题）才说明真正理解了。

### 5. 错误是信息源

错误解答不是垃圾，而是诊断卡点的最好材料。"为什么我会这样错"比"正确答案是什么"更有价值。

### 6. 计划要尊重人的限制

学习计划不能排满，要留缓冲。每天超负荷的计划不是计划，是焦虑源。

### 7. 一个 Skill 只解决一个问题

不要试图用一个 Skill 覆盖所有场景。零基础学习、模糊理解诊断、深化、解题、错题复盘——这是不同的问题，需要不同的方法。

### 8. 面向具体人群

这个项目面向高中到本科低年级的理工科学生。这意味着：
- 不假设研究者级别的数学成熟度
- 不用更高阶知识来解释当前知识
- 使用他们已有的知识体系（中学数学/物理基础）作为桥梁

## 什么不是这个项目

- 不是教材的替代品
- 不是刷题工具
- 不是"AI 老师"的人格化尝试
- 不是对"翻转课堂""项目式学习"等教学理念的实现
