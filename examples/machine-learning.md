# 机器学习学科案例

本文档展示 Scientific Learning Skills 在机器学习/深度学习概念上的诊断式讲解效果。

---

## 1. softmax 是什么？（零基础）

**Skill**: `zero-base-learning`

**直觉**：你有 10 个候选人，每人有一个"能力分"，你要选一个。softmax 做的事：把每个人的能力分转成"被选中的概率"——分高的人概率大，但分低的人也不是零。

**正式定义**：softmax(x_i) = e^{x_i} / Σ e^{x_j}。指数函数保证输出为正值，分母求和保证所有概率加起来等于 1。

**常见误区**：

| 常见错误 | 为什么错 | 正确理解 |
|----------|---------|---------|
| softmax 输出就是 one-hot | softmax 输出是概率分布，不是离散选择 | softmax 输出每个类的概率，argmax 之后才是 one-hot |
| softmax 和 sigmoid 是一回事 | sigmoid 用于二分类，softmax 是多分类泛化 | 二分类时 softmax 退化为 sigmoid，但多分类只能用 softmax |

## 2. batch size 为什么影响训练？（云里雾里）

**Skill**: `fuzzy-understanding`

**诊断**：你的卡点可能是把 batch size 当成了一个"随便设的数值"，而不是"梯度的质量-效率权衡"。

**直觉**：
- 小 batch：每次看 4 张图 → 方向有点抖但步子快 → 像骑自行车不停微调方向
- 大 batch：每次看 256 张图 → 方向很准但每一步都很慢 → 像开卡车转弯慢但稳

**正式理解**：
- 小 batch：高方差梯度 → 噪声有助于跳出局部极小 → 泛化通常更好
- 大 batch：低方差梯度 → 梯度估计更准 → 更容易收敛到尖锐极小（泛化差）

**常见误区**：

| 常见错误 | 为什么错 | 正确理解 |
|----------|---------|---------|
| batch size 越大越好 | 大 batch 虽然梯度更准，但泛化通常更差 | batch size 是泛化-效率的权衡，不是越大越好 |
| batch size 必须是 2 的幂 | 只是 GPU 内存对齐的习惯 | 任意整数都能跑，但 2 的幂在硬件上略快 |

## 3. ResNet 为什么加残差？（云里雾里）

**Skill**: `fuzzy-understanding`

**诊断**：你的卡点可能是把残差连接当成了"多了一步计算"，而不是"给梯度留了一条高速公路"。

**直觉**：普通网络：输入 → [一堆层] → 输出。层越深，信号越容易"衰减消失"。ResNet：输入 → [一堆层] + 输入本身 → 输出。那个 "+ 输入本身" 就是**残差连接**——它保证即使中间的层什么都不学（输出零），至少原始信号能传过去。

**正式理解**：传统网络学 H(x)，ResNet 学 F(x) = H(x) - x。如果最优映射接近恒等映射（很多层不需要改变信号），学 F(x) ≈ 0 比学 H(x) ≈ x 容易得多。

**常见误区**：

| 常见错误 | 为什么错 | 正确理解 |
|----------|---------|---------|
| 残差连接只是把输入"复制了一份" | 忽略了它的梯度意义 | 残差连接给梯度提供了一条不经过任何变换的直达路径，缓解梯度消失 |
| ResNet 层数越多效果一定越好 | ResNet-1202 在 CIFAR-10 上不如 ResNet-110 | 过深的 ResNet 仍然会过拟合，残差连接缓解但不能完全解决退化 |

## 4. 多 GPU 数据并行时，为什么梯度可以各算各的再汇总？（云里雾里）

**Skill**: `fuzzy-understanding`

**诊断**：你的卡点可能是对"梯度"和"求导"的线性性质理解不到位。

**直觉**：4 个人各算各的账本，最后把总数加起来除以 4。因为"求导"这个操作是**线性的**——先求导再加 = 先加再求导——所以各 GPU 独立算梯度再取平均，等价于用一个超大 batch 一起算。

**正式理解**：损失函数 L = (1/N) Σ L_i。由于求导是线性算子，∇L = (1/N) Σ ∇L_i。因此各 GPU 可以独立计算自己那部分数据的 ∇L_i，然后 all-reduce 取平均。

**常见误区**：

| 常见错误 | 为什么错 | 正确理解 |
|----------|---------|---------|
| "各算各的"等于各 GPU 学了不同的东西 | 梯度在参数服务器/ring all-reduce 中做了平均 | 所有 GPU 最终用的是同一份平均梯度，参数更新一致 |
| 梯度平均 = 模型平均 | 平均的是梯度（方向），不是参数（位置） | 参数仍然是同一份，只是更新方向是各 GPU 梯度方向的平均 |

## 5. BatchNorm 为什么有用？（深化）

**Skill**: `deepening-learning`

**多视角理解**：

1. **优化视角**：BatchNorm 通过归一化每层输入，减少了内部协变量偏移（Internal Covariate Shift），使每层的输入分布保持稳定，允许使用更大的学习率。

2. **正则化视角**：BatchNorm 在每个 mini-batch 上计算均值和方差，引入了噪声——这起到了类似 Dropout 的正则化效果，减轻过拟合。

3. **梯度视角**：BatchNorm 使损失曲面更平滑，减少了梯度对参数尺度的敏感性，缓解梯度消失/爆炸。

**跨知识联系**：BatchNorm 和 LayerNorm、InstanceNorm、GroupNorm 的核心区别在于**归一化的维度不同**——BatchNorm 在 batch 维度，LayerNorm 在 feature 维度。Transformer 用 LayerNorm 是因为序列长度不一、batch 维度上统计不稳定。

**常见误区**：

| 常见错误 | 为什么错 | 正确理解 |
|----------|---------|---------|
| BatchNorm 在推理时还用小批量统计 | 推理时 batch 可能只有 1 个样本 | 推理时使用训练期间累积的滑动平均均值和方差 |
| BatchNorm 消除了对 Dropout 的需求 | 二者的正则化机制不同 | 实践中 BatchNorm + 低强度 Dropout 组合使用仍然有效 |
